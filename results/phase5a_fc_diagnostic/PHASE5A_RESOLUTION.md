# Phase 5A Resolution — Diagnostic Pearson FC Construction

## 1. Purpose

Build the Pearson functional-connectivity (FC) representation for the authoritative 780-subject cohort under **Option 1** (Phase 4.2's authoritative decision for this phase): retain all subjects and all 116 ROIs, and preserve every mathematically undefined correlation explicitly as NaN. This is a diagnostic/audit construction — no Fisher-Z was applied to real data, no full FC dataset was written to disk, and no downstream model was trained.

## 2. Authoritative Cohort

780 subjects (351 ASD, 429 Control), 20 sites — re-verified unchanged from Phase 2 at the start of this script. Source data: `abide_pcp/ABIDE_pcp/cpac/filt_global/*_rois_aal.1D`, 780/780 coverage, unchanged (fingerprint-verified).

## 3. FC Mathematical Definition

For subject *s* and ROI columns *i*, *j* of that subject's *T × 116* time series: Pearson *r(i,j) = cov(i,j) / (std(i) · std(j))*. This is undefined (0/0) whenever *std(i) = 0* or *std(j) = 0* — a property of the definition, not an implementation artifact. `numpy.corrcoef` returns NaN for exactly these cases, which was independently re-verified against a hand-written covariance/std formula (see §6).

## 4. Feature Indexing Convention

**Fixed, deterministic, and to be used for the remainder of this project without reordering:**
0-indexed ROI pairs (i, j) with i < j, generated by a row-major nested loop (outer i = 0..114, inner j = i+1..115); `feature_index` runs 1..6,670; `roi_i`/`roi_j` are reported as 1-indexed ROI numbers matching the Phase 4.1 convention. By symmetry (*r(i,j) = r(j,i)*), this single ordering fully determines the "lower triangle" extraction — there is no separate upper/lower distinction in value, only in which index is reported first, and this convention fixes that unambiguously. Recorded in `fc_feature_index.csv` (6,670 rows, verified).

## 5. Undefined-Correlation Definition

A feature (i,j) is undefined for subject *s* if and only if ROI *i* or ROI *j* has zero variance in that subject's time series (per Phase 4.1's constant-ROI audit). This was verified — not assumed — for all 780 subjects × 6,670 features in this phase (§6).

## 7. The 14,025-Entry Cross-Check

`sum(undefined FC entries across all 780 subjects) = 14,025` — computed fresh in this phase by actually building and inspecting every subject's 116×116 correlation matrix (not re-derived combinatorially as in Phase 4.1/4.2). **Matches the expected value exactly. Cross-check: PASS.** No discrepancy investigation was needed.

## 8. Missingness Distribution

- 2,014 of 6,670 features (30.2%) are undefined for at least one subject; the remaining 4,656 (69.8%) are never undefined for any of the 780 subjects.
- 457 features (6.9%) are undefined for ≥1% of subjects.
- Only **2** features reach ≥5% of subjects; **none** reach ≥10%, ≥25%, or ≥50%.
- The single most-affected feature (Cerebelum_7b_R × Cerebelum_10_L) is undefined for 43/780 subjects (5.5%) — this is the worst case across all 6,670 features.
- The top affected pairs are dominated by combinations involving Cerebelum_7b_R and other cerebellar/vermis and orbitofrontal ROIs — consistent with, but not proof of, the Phase 4.1/4.2 clustering findings. **This is reported strictly as a data-quality/missingness pattern, not interpreted as a biomarker or connectivity finding.**

## 9. Fisher-Z Implications

Not applied to real data in this phase. Established mathematically: for defined *r*, *z = arctanh(r)* is computable; for undefined *r*, *z* remains undefined (NaN propagates through `arctanh`, it does not resolve it). **0 exact +1 and 0 exact −1 correlations** were found among all defined entries across the full cohort, so **clipping before `arctanh` would not currently be required** — but this was verified, not assumed, and should be re-checked if the underlying data or cohort ever changes.

## 10. SVM-RFE Compatibility

Empirically tested against the installed scikit-learn (1.7.2), using small synthetic data only (not this project's real FC data, and no training on real data occurred): `StandardScaler` tolerates NaN, but `SVC` and `RFE(SVC(...))` — the standard scikit-learn SVM-RFE construction — both raise `ValueError: Input X contains NaN` immediately. **A 6,670-feature matrix containing the 14,025 NaN entries from §7 cannot be passed directly into a standard SVM-RFE step.** Full detail: `svm_rfe_nan_compatibility.md`.

## 11. What Remains Unspecified

**Retaining NaN through this diagnostic phase does not resolve the downstream problem — it only confirms the problem is well-characterized and mathematically clean.** Before SVM-RFE can run, a decision is still required on: (a) whether to exclude the 47 affected subjects, (b) whether to exclude the 19 affected ROIs, (c) whether to adopt some documented numeric convention (none was found to be paper-specified, per Phase 4.2), or (d) some other resolution not yet considered. The paper itself specifies none of these.

## 12. Exact Decision Required Before Final FC Preprocessing

The current, and only, methodological decision in force is:

> **"Retain all 780 subjects and 116 ROIs; preserve undefined Pearson correlations explicitly as NaN until a downstream numerical handling strategy is formally documented."**

This is a holding position, not a resolution. Before Phase 5 can proceed past this diagnostic stage into Fisher-Z-on-real-data and SVM-RFE, a human decision is required on how the 14,025 NaN entries will be converted into a finite input SVM-RFE can accept.
